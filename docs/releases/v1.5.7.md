# Dikta v1.5.7 — Reliable Read Aloud

Read Aloud handles longer selections more reliably, including Nicole's slower delivery. Nicole at 1.25× uses smaller planned chunks, and any voice's chunk explicitly rejected for overlong audio is split into smaller pieces before playback. Reading still starts with the first generated chunk while the next is prepared; your chosen voice and speed are preserved.

Fixed an intermittent app crash when reading terminal selections through the clipboard fallback. Deadline checks and sleep durations now handle timing boundaries safely, with regression coverage for cancellation, focus changes, and invalid timing inputs.

The Read Aloud start cue now follows playback scheduling rather than preparation, and About keeps “Check for Updates…” available when no pending update is known.

Dikta now keeps the Hotkeys menu focused on Record, Push-to-Talk, and Read Aloud. The retired Format Selection command and its formatter are removed. Existing `hotkeys.format_selection` settings from older versions are safely ignored and disappear on a normal settings save; Cmd-Shift-F is no longer reserved and can be assigned to a surviving hotkey.

Multi-line output, including Debrief summaries, now preserves the clipboard's full supported contents while it requests a paste, then restores them only when Dikta still owns the clipboard. If the clipboard changes or its original contents cannot be safely preserved, Dikta skips the paste and keeps the result in History instead.

Debrief completion messages now distinguish a requested paste from an available result with processing warnings or a skipped paste.

Dikta v1.5.7 requires macOS 15 or later. Read Aloud remains unavailable on macOS 26.4–26.5.
