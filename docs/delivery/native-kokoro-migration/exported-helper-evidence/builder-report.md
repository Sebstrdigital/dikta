## Isolation breach, correction, and proof

An earlier shell-prefix/build-setting attempt did **not** propagate `DIKTA_REAL_SESSIONS_DIR` into the Xcode test host. That invalid run executed 790 tests with one skip and failed two assertions in one real-transcript test (exit `65`). It is not treated as a baseline. No private recording content is reproduced here.

The correction was a temporary shared scheme, `Dikta-IsolatedValidation`, with this test-host environment value:

`DIKTA_REAL_SESSIONS_DIR=/tmp/dikta-native-kokoro-isolated-empty-sessions`

Before any later broad run:

1. The isolated directory was created and confirmed empty.
2. `xcodebuild build-for-testing` generated `/tmp/dikta-native-kokoro-isolation-derived-20261009-045907/Build/Products/Dikta-IsolatedValidation_macosx27.0-arm64-x86_64.xctestrun`.
3. The generated `.xctestrun` was inspected and positively showed the exact environment variable above; see `isolation-xctestrun-verification.log`.
4. A focused `DebriefRealTranscriptTests` runtime probe used the isolated path and skipped for lack of local sessions; exit `0`. No recording content was displayed.

The scheme hardcoded the unique, known-empty `/tmp` path because shell and command-line build-setting injection had proven insufficient for the launched test host. It is validation machinery, not a portable product setting, and therefore does **not** belong in the final candidate. After testing/export, it was moved out of the project and preserved as evidence at `Dikta-IsolatedValidation.xcscheme`. `xcodebuild -list` then again showed the normal autogenerated `Dikta` scheme.
